# Стёпа ↔ Саймон

Это дополнение для уже работающего собственного Саймона на Яндекс Станции. Оно не является готовым навыком Алисы и не устанавливает Саймона на обычную колонку. Проект самой колонки и его учётные данные сюда не входят.

`plant_gateway.py` и `plant_audio.py` — текущие модули интеграции из рабочей установки. Они предназначены для пакета `steve`: используют относительные импорты и `steve.core.Audio`. Не запускайте их как отдельную программу. Автоматический патчер старой версии намеренно не включён: он не соответствует последним изменениям воспроизведения.

## Контракт сервера

В конфигурации бота включите `character_gateway_enabled`, задайте host `127.0.0.1`, port `8798` и отдельный секрет `character_gateway_token` длиной от 32 символов. Оба сервиса в этой конфигурации находятся на одном VPS.

POST `http://127.0.0.1:8798/v1/character/events`, заголовки `Content-Type: application/json`, `Authorization: Bearer <секрет>`.

```json
{
  "request_id": "unique-id-for-this-utterance",
  "source": "simon_bridge",
  "text": "показания",
  "metadata": {"speaker": "Егор", "room": "Яндекс Станция"}
}
```

Ответ содержит `text` для экрана и `speech_text` для озвучки. Для каждого нового вопроса нужен новый request_id; повтор запроса использует кэш. Источники: `simon_bridge` или `yandex_station`. `speaker` — доверенная роль домашнего адаптера, не голосовая биометрия. Не принимайте произвольный speaker из открытого интернета.

401 — неверный ключ; 400 — неверный запрос; 429 — занят/лимит; 503 — временная ошибка. Не превращайте ошибки в вымышленные показания.

## Подключение в исходниках Саймона

1. Сохраните рабочую версию Саймона. Добавьте оба модуля в его пакет `steve`. Не перезаписывайте другие модули вслепую.
2. Скопируйте пример настроек в `/etc/steve/plant-gateway.json`, вставьте секрет шлюза. Дайте чтение только пользователю сервиса Саймона. Вызовите `load_plant()` один раз при старте worker.
3. После распознавания фразы и удаления обращения «Саймон», перед обычной генерацией, вызовите `plant.answer(remainder, guard=...)`. `None` означает обычный вопрос Саймону; строка — готовый ответ Стёпы.
4. Верните эту строку в обычный TTS. Не отправляйте её повторно в генератор Саймона и не используйте короткий literal reader, запрещающий цифры или длинные ответы.
5. Для plant-ветки можно собрать результат TTS через `phrase_frames(tuple(audio_parts))` до передачи проигрывателю. Он сохраняет PCM и делит длинную речь только по паузам; ожидается формат `Audio` вашего Саймона, mono PCM16 LE 16 kHz. Проверяйте совместимость вашего аудиоконтракта.
6. Сохраните STOP и проверку актуальности поколения до/после сетевого вызова, синтеза и перед каждым воспроизведением. `CancellableCall` прекращает ожидание и отбрасывает поздний ответ; уже принятую сервером запись это не отменяет. Не повторяйте команды записи автоматически.
7. Закрепите изменения в основном репозитории Саймона и его процедуре обновления. Эти файлы сами по себе не заменяют интеграцию в worker/stream.

Диагностика `diagnostic_once` по умолчанию не активна; не создавайте её управляющие файлы при обычной работе.

## Проверка у колонки

- «Саймон», после сигнала: «Спроси у цветка, как дела» — ответ от лица Стёпы.
- «Цветок, показания» — почва по относительной шкале, свет, температура и влажность; понятные числа словами.
- «Стёпа, когда тебя поливали» — понятная дата из общей памяти.
- «Стёпа, я полил» — сначала просьба подтвердить. «Стёпа, подтверждаю полив» записывает событие один раз.
- STOP во время ожидания и речи прекращает воспроизведение; обычные вопросы и музыка Саймона продолжают работать.

Это инструкция для интеграции с вашей версией Саймона, а не обещание совместимости с любым его форком. Сам Telegram-бот полностью работает без колонки.
