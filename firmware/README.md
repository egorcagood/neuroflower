# Прошивка ESP32-S3

Поддерживаемая конфигурация: HW678 V6.0.0 / ESP32-S3 N16R8, 16 МБ flash. PSRAM не используется. Прошивка только читает датчики и пишет в USB Serial и UART0; управлять поливом она не умеет.

1. Установите VS Code и расширение PlatformIO IDE. Откройте именно эту папку `firmware` как проект.
2. Подключите собранную по [схеме](../docs/wiring.md) плату кабелем с передачей данных. Посмотрите COM-порт в Диспетчере устройств Windows.
3. Нажмите Build, затем Upload. Если подключено несколько плат, укажите свой порт в `platformio.ini`: `upload_port = COM6`, `monitor_port = COM6` — COM6 лишь пример.
4. Откройте Serial Monitor: 115200 бод, DTR=0, RTS=0. Не держите его открытым одновременно с ботом или мостом: они используют тот же порт.

Эквивалент в терминале PlatformIO, из этой папки:

```sh
pio run -e esp32s3-usb
pio run -e esp32s3-usb -t upload --upload-port COM6
pio device monitor -b 115200 -p COM6 --dtr 0 --rts 0
```

На macOS/Linux замените COM6 на порт своей платы. При ошибке входа в загрузчик зажмите BOOT, кратко нажмите RESET, отпустите BOOT и повторите Upload. Сверьте названия кнопок и USB-разъёмов своей платы. Зелёный светодиод доказывает наличие питания, но не передачу данных.

Ожидаемый формат, числа здесь вымышлены:

```text
uptime_s=120 | soil_raw=3000/4095 | soil_mV=2500 (uncalibrated) | light_lux=850.0 | temperature_C=23.50 | air_RH_pct=42.00
```

Строка появляется примерно раз в две секунды. `uncalibrated` нормально: плата передаёт исходное измерение, а пользовательская калибровка хранится в боте. `NOT_FOUND`, `READ_ERROR`, `I2C_BUS_NOT_IDLE` требуют проверки соединений и пайки, а не подстановки красивых чисел.

Готовые бинарники с личными настройками здесь не распространяются. PlatformIO собирает прошивку из открытого исходника и сам загружает её с нужными адресами flash. Wi-Fi, паролей и API-ключей в этой USB-прошивке нет.
